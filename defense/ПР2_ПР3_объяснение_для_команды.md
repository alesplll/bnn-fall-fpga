# ПР2 и ПР3: объяснение проекта для команды и защиты

Этот текст рассчитан на человека, который впервые открывает проект. Начните с разделов 1–4, затем разберите демонстрацию и вопросы в конце. **Числа ресурсов и ускорение называйте только после нового прогона Vivado:** код подготовлен, но итоговые отчёты для обновлённого проекта ещё не получены.

**Словарь на старте:** ПЛИС — микросхема, в которой можно построить свою цифровую схему. RTL — код, описывающий эту схему на Verilog. Vivado сначала синтезирует RTL в логические элементы, затем размещает их в кристалле и прокладывает соединения; XSim внутри Vivado выполняет симуляцию кода без платы.

## 1. Что вообще делает проект

Мы определяем, похоже ли движение человека на падение. Исходные записи SisFall содержат данные акселерометра и гироскопа. В ПР1 программа извлекла из них пять признаков, обучила небольшую сеть и подготовила **эталонные ответы** для проверки аппаратной реализации.

Пять признаков: ускорение в момент пика, угол наклона относительно начальной ориентации, максимальная угловая скорость около пика, скорость изменения ускорения (`jerk`) и дисперсия ускорения после пика. Каждый признак преобразован в знаковое восьмибитное число (`int8`). Сам поиск пика и расчёт этих признаков выполняется программой; **Verilog получает уже готовые пять чисел**, а не сырые показания датчиков.

Сеть имеет вид **5 → 8 → 1**:

```text
5 чисел int8 → слой A: 8 нейронов → 8 бит → слой B → 1 бит
                                                     1 = падение
                                                     0 = другая активность
```

Важно различать два вида проверки. Сравнение с настоящими метками датасета показывает качество распознавания; в ПР1 на тестовой выборке получили accuracy 97,0 %, precision 84,5 %, recall 93,6 %. Сравнение Verilog с **целочисленной программной моделью** показывает, правильно ли аппаратный код повторяет вычисления. Для ПР2–ПР3 используется именно второй вид проверки. Совпадение с программой не означает, что сеть безошибочно распознаёт каждое реальное падение.

| Работа | Главный результат | Что проверяем |
| --- | --- | --- |
| ПР1 | Обученная программная модель, веса, эталонные входы и ответы | Качество классификации и подготовка эталона |
| ПР2 | RTL-классификатор на Verilog | Совпадение его вычислений с программным эталоном в симуляции |
| ПР3 | Прототип для выбранного кристалла и эксперимент с регистрами | Симуляция верхнего модуля, синтез, размещение, трассировка, ресурсы и тайминги |

## 2. Данные, которые переходят из ПР1 в Verilog

Вход — одно 40-битное слово `input_features = {x0, x1, x2, x3, x4}`. Пять байтов идут от старшего к младшему. Например, запись `input_features[39 - 8*j -: 8]` в цикле берёт байт признака `j`: при `j=0` это биты 39:32, при `j=1` — 31:24 и так далее. Обозначение `-: 8` означает «восемь бит вниз от указанной позиции».

Каталог [`weights/`](../weights/) содержит обычные текстовые hex-файлы для `$readmemh`:

| Файлы | Содержимое |
| --- | --- |
| `weights_layerA_W.mem`, `weights_layerA_b.mem` | 40 восьмибитных весов и 8 смещений первого слоя |
| `weights_layerB_W.mem`, `weights_layerB_b.mem` | 8 однобитных весов и смещение второго слоя |
| `tb_inputs_full.mem`, `tb_expected_full.mem` | 2331 вход и ожидаемый итоговый бит |
| `tb_hidden_full.mem`, `tb_score_full.mem` | Ожидаемые 8 промежуточных бит и сумма второго слоя |
| `tb_inputs_64.mem`, `tb_expected_64.mem` | Небольшая контрольная подборка из 64 входов и ответов |

Все 64 контрольных входа взяты из полного тестового набора. **2331 вектор** нужен для тщательной сверки классификатора в симуляции. **64 вектора** нужны для компактной самопроверки верхнего модуля прототипа. Это два масштаба проверки одной сети, а не две разные модели.

Запись `reg [7:0] w_a [0:39]` означает **массив из 40 элементов по 8 бит**, а не одно 320-битное число. `reg [0:0] w_b [0:7]` означает **8 элементов по 1 биту**; `w_b[h][0]` выбирает бит веса нейрона `h`. Именно явная однобитная ширина и обращение к `[0]` были внесены в исходный RTL после замечания на защите. Скобки до имени задают ширину элемента, скобки после имени — количество элементов массива.

## 3. ПР2: как работает RTL-классификатор

Главный файл — [`rtl/bnn_classifier.v`](../rtl/bnn_classifier.v). Он описывает вычисления сети и интерфейс:

| Сигнал | Смысл |
| --- | --- |
| `clk` | Тактовый сигнал |
| `rst_n` | Синхронный сброс, активен при 0 |
| `valid_in` | На входе находится действительное слово признаков |
| `input_features[39:0]` | Пять упакованных знаковых байтов |
| `valid_out` | Выход относится к действительному входу |
| `fall_detected` | Итоговый бит классификации |

### Слой A: восемь сумм произведений

Для каждого скрытого нейрона `h` вычисляется сумма:

```text
z[h] = b_A[h] + x[0]·W_A[0,h] + ... + x[4]·W_A[4,h]
hidden[h] = 1, если z[h] ≥ 0; иначе 0
```

Порядок весов в файле: адрес `j*8+h` — это вес признака `j` для нейрона `h`. Входы и веса трактуются как **знаковые int8** через `$signed`; произведение хранится в 16 битах, сумма — в 32 битах. Расширение знака перед сложением нужно, чтобы отрицательные произведения не превратились в большие положительные числа. Проверка `>= 0` включает ноль — так же работает программный эталон.

### Слой B: XNOR, подсчёт совпадений и решение

У второго слоя восемь входных битов и восемь однобитных весов. XNOR выдаёт 1, когда бит активации совпал с битом веса. `popcount` — число единиц, то есть число совпадений от 0 до 8. Итоговая формула:

```text
score = 2·popcount(XNOR(hidden, W_B)) − 8 + b_B
fall_detected = 1, если score ≥ 0
```

Например, если совпали 6 из 8 битов, часть без смещения равна `2·6−8 = 4`. Формула заменяет умножения бинарных значений `−1/+1` простыми логическими операциями и подсчётом.

### Где здесь регистры

`always @*` описывает **комбинационную логику**: при изменении входа пересчитываются оба слоя. Слово `reg` в объявлении переменной само по себе ещё не означает физический триггер. Физические регистры создаёт блок `always @(posedge clk)`: на фронте такта он записывает `fall_detected` и `valid_out`. При `valid_in=0` последний ответ сохраняется, но `valid_out` становится 0. При `rst_n=0` оба выхода сбрасываются.

### Как проверяется ПР2

[`rtl/tb_bnn_classifier.v`](../rtl/tb_bnn_classifier.v) — тестбенч. Он подаёт вход **до** фронта такта и сравнивает зарегистрированный ответ с эталоном **после** фронта. В полном режиме проверяются 2331 выхода, все восемь бит `hidden` и число `score`; отдельно проверяются 14 граничных входов с `−128`, `127` и нулём. Это помогает найти ошибку даже тогда, когда случайно совпал итоговый бит. Локальные прогоны проходят; окончательное подтверждение для обновлённого проекта должно прийти из XSim в Vivado 2022.2.

## 4. ПР3: что добавлено к ПР2

**Верхний модуль** — модуль с внешними входами и выходами, с которого Vivado начинает сборку схемы. В [`fpga/fpga_top.v`](../fpga/fpga_top.v) верхний модуль содержит классификатор, 64 контрольных входа и 64 ожидаемых ответа, а также автомат подачи тестов. Это прототип для выбранного кристалла, который можно проверить в симуляции без реальной платы.

Автомат исходного прототипа имеет три состояния:

```text
IDLE: ждёт start → DRIVE: подаёт очередной вход → CHECK: сверяет ответ
                                                  │
                        следующий вход ←──────────┘
```

Он считает проверенные слова (`checked_count`) и расхождения (`error_count`). После 64-го входа выставляет `done` и `pass`; повторный `start` начинает новую проверку. **Автомат находится в верхнем модуле, а не внутри нейросети.** Он отвечает за подачу тестовых данных, а не за вычисление нейронов. Тестбенч проверяет успешный прогон, намеренно изменённый эталонный бит и повторный успешный прогон.

### Зачем появился конвейер

После замечания преподавателя мы выделили вычисления в [`bnn_layer_a.v`](../rtl/bnn_layer_a.v) и [`bnn_layer_b.v`](../rtl/bnn_layer_b.v) и поставили регистр **между слоями**, а не после каждой операции. Для честного сравнения сделаны два варианта из **тех же самых модулей**:

```text
Без регистра: входной регистр → слой A → слой B → выходной регистр
С регистром: входной регистр → слой A → регистр 8 бит + valid → слой B → выходной регистр
```

Вариант без промежуточного регистра — [`bnn_classifier_modular.v`](../rtl/bnn_classifier_modular.v), с ним — [`bnn_classifier_pipelined.v`](../rtl/bnn_classifier_pipelined.v). `hidden_q` хранит восемь бит слоя A, `valid_hidden_q` передаёт вместе с ними признак действительности. Если забыть задержать `valid`, выход можно ошибочно связать с соседним входом.

Если на некотором фронте входной регистр принял вектор, вариант без нового регистра выдаёт ответ на следующем фронте; конвейерный — ещё на один фронт позже. **Оба способны принимать новый вектор каждый такт.** Поэтому задержка одного ответа увеличивается, а возможная пропускная способность зависит от того, насколько коротким стал самый длинный путь между регистрами. Сам факт добавления регистра ещё не доказывает ускорения: первый слой может остаться критическим путём.

[`fpga/fpga_top_pipelined.v`](../fpga/fpga_top_pipelined.v) подключает конвейер к самопроверке и задерживает индекс ожидаемого ответа вместе с данными. Он подаёт 64 слова подряд и затем ждёт последние ответы. **Сравнивать число тактов этого автомата с исходным автоматом нельзя как доказательство ускорения регистром:** способ подачи тестов у них тоже различается.

### Как измеряем именно вычислительный тракт

Для измерений есть [`fpga/bnn_benchmark.v`](../fpga/bnn_benchmark.v): одинаковые внешние входы, одинаковый входной регистр, одинаковые веса и модули слоёв, один кристалл и одни ограничения. Разница между вариантами — промежуточный регистр. Входы остаются **переменными**, а не берутся из встроенных 64 констант. Иначе Vivado мог бы упростить схему под заранее известный набор и сравнение размеров стало бы недостоверным.

Сравниваются результаты **после размещения и трассировки** при целевых периодах 20 и 10 нс. В отчёте Vivado смотрим:

| Термин | Что означает и как объяснить |
| --- | --- |
| LUT | Программируемые логические таблицы, реализующие часть вычислений |
| Slice Register | Физические триггеры; при добавлении конвейера их обычно становится больше |
| Критический путь | Самый медленный из учитываемых путей между регистрами |
| WNS | Запас времени по худшему setup-пути; положительный означает, что заданный период для этих путей выдержан |
| Трассировка | Размещение соединений между физическими ресурсами кристалла |
| `route_status.rpt` | Сколько цепей проложено полностью и есть ли ошибки маршрутизации |

Оценку частоты по одному прогону можно вычислить как `1000 / (заданный период − WNS)` МГц, если значения в наносекундах. Это **оценка для ограниченных внутренних синхронных путей**, а не измеренная частота на плате. У внешних входов и выходов здесь нет задержек и распиновки, поэтому делать вывод о скорости всей физической системы нельзя.

## 5. Один проект Vivado и что в нём искать

[`vivado/create_project.tcl`](../vivado/create_project.tcl) создаёт **один** проект `vivado_pr23/bnn_pr23.xpr` под кристалл `xc7a100tcsg324-1` (семейство Artix-7). Это обозначение кристалла, **не модель платы**. [`vivado/run_all.tcl`](../vivado/run_all.tcl) последовательно переключает верхний модуль этого проекта, запускает симуляции, синтез, размещение и трассировку и складывает результаты в `vivado_pr23/results/`.

Главные папки результатов:

| Папка | Что показывает |
| --- | --- |
| `pr2_classifier` | Синтез отдельного ядра ПР2 |
| `baseline_20`, `pipeline_20` | Сравнение вычислительного тракта при цели 20 нс |
| `baseline_10`, `pipeline_10` | То же при цели 10 нс |
| `pr3_prototype_20`, `pr3_pipeline_20` | Реализация двух прототипов с контрольной памятью |
| `simulations` | Логи поведенческой и функциональной симуляции |

В каждой папке варианта находятся `result.txt`, отчёт ресурсов, лог синтеза и снимок схемы `synth.dcp`; у реализованных вариантов также есть отчёты тайминга, маршрутизации, DRC и `routed.dcp`. Скрипт сохраняет эти снимки, потому что в окне Vivado после полного прогона активен только **последний** верхний модуль. Открытие другого `.dcp` позволяет посмотреть именно его схему или размещение; это не другой исходный проект.

### Короткая демонстрация на защите

1. Открыть `vivado_pr23/bnn_pr23.xpr`. В Sources показать `bnn_classifier.v`, слои A/B, `bnn_classifier_pipelined.v`, верхние модули и тестбенчи.

3. Для ПР3 показать `sim_pr3_behavioral.log` и `sim_pr3_pipeline_behavioral.log`: самопроверка 64 векторов, обнаружение ошибки и повторный запуск. Открыть `pr3_pipeline_20/routed.dcp` в Device, затем `route_status.rpt`.
4. Для эксперимента открыть `baseline_20` и `pipeline_20`: сравнить `utilization_routed.rpt`, `timing_routed.rpt`, `critical_paths.rpt` и `result.txt`. Если важно показать различие в топологии, открыть их `synth.dcp` по очереди.
5. Сказать, выдержан ли период и есть ли ускорение, **только по полученным отчётам**. Если WNS отрицательный, соответствующий период не выдержан. Не заменять численные отчёты картинкой логической схемы.

Для запуска на Windows в Tcl Console Vivado 2022.2:

```tcl

source vivado/run_all.tcl
```

Строка `PR23_DONE` означает, что все этапы завершились; она **не означает**, что оба периода обязательно выдержаны. Сообщение `TIMING_NOT_MET` отмечает вариант с отрицательным WNS. Новые результаты нужно брать из текущей папки `vivado_pr23/results/`, а не из ранее собранного PDF.

## 6. Что честно говорить о границах работы

- Весовые файлы загружаются при сборке через `$readmemh`; это **параметры уже обученной сети**, а не обучение внутри ПЛИС.
- Синтезированная схема с фиксированными 64 входами может сильно упроститься. Это допустимо для самопроверки, но размер и частоту вычислительного ядра мы сравниваем по вариантам **с переменным входом**.
- Предупреждение о реализации маленькой памяти в регистрах само по себе не означает ошибку ответа. Любое предупреждение о непрочитанном `.mem`, отключённой логике или нарушении тайминга надо разобрать по логу; нельзя автоматически назвать все предупреждения безвредными.
- Выбрана микросхема `xc7a100tcsg324-1`, но конкретная отладочная плата и её распиновка не заданы. Битовый поток не создавался, испытаний на плате не было. DRC может предупреждать об I/O-стандарте и выводах; это не нужно скрывать. Проверены симуляция и реализация **для выбранного кристалла**, если новый прогон Vivado их подтвердит.
- Сейчас локально прошли проверки исходного и конвейерного RTL, включая 2331 полных и 14 граничных векторов. **Итоговые LUT, WNS и ускорение обновлённого проекта пока не подтверждены новым Vivado-прогоном.** Поэтому старые числа из PDF на защите не называем; после получения новых отчётов и PDF этот абзац нужно обновить.

## 7. Готовые ответы на частые вопросы

**Что именно сделано в ПР2?** Перенесён целочисленный вывод обученной сети в Verilog и проверено, что ответы и промежуточные значения совпадают с программным эталоном.

**Что именно сделано в ПР3?** RTL подключён к верхнему модулю с самопроверкой. Подготовлены один проект Vivado для Artix-7 и сравнение тракта без промежуточного регистра и с ним. Обновлённый вариант нужно прогнать в Vivado; итоговый вывод об ускорении делается по новым отчётам трассировки.

**Почему 2331 и 64?** 2331 — полный тест для сверки вычислений. 64 — компактная часть тех же данных внутри прототипа для проверки его автомата и счётчиков.

**Почему `reg` в комбинационном блоке не обязательно регистр?** В Verilog это тип переменной, которой присваивают значение процедурно. Триггер появляется, когда значение сохраняется по фронту `clk`, как в `always @(posedge clk)`.

**Чем конвейер быстрее, если ответ приходит позже?** Возможность ускорения относится к **частоте тактов и потоку входов**: длинный путь A→B разбит на два. Отдельный ответ при этом задерживается ещё на такт. Действительный выигрыш определяется WNS и критическим путём, а не самим наличием регистра.

**Зачем нужен `valid`?** Это метка, что данные на входе или выходе относятся к настоящему вектору. В конвейере она задерживается вместе с восемью битами, иначе ответ можно сопоставить не с тем входом.

**Почему схема прототипа может оказаться меньше схемы классификатора?** В прототипе встроены 64 постоянных входа. Синтезатор может убрать вычисления, которые не влияют на ответы именно для этих констант. Для сравнения ядра используются отдельные варианты с изменяемым входом.

**Есть ли здесь нейросеть на ПЛИС целиком?** На ПЛИС реализован её **этап вывода** для пяти заранее вычисленных признаков. Извлечение признаков и обучение выполнялись программно в ПР1.

**Что сказать про плату?** Конкретная плата не задана, поэтому испытание на ней не проводилось. Показать можно модель, симуляцию, синтез, размещение и трассировку для выбранного кристалла; работу физических датчиков или выводов не заявляем.

## 8. Объяснение за минуту
