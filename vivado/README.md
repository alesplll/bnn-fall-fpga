# Единый проект Vivado 2022.2 для ПР2 и ПР3

Откройте Vivado 2022.2 на Windows. В **Tcl Console** выполните из корня
репозитория (путь замените, если он другой):

```tcl
cd D:/neuroproc/bnn-fall-fpga
source vivado/run_all.tcl
```

Сценарий создаёт один проект `vivado_pr23/bnn_pr23.xpr` для
`xc7a100tcsg324-1` и выполняет шесть поведенческих симуляций. Затем он
синтезирует отдельное ядро ПР2, строит исходный и конвейерный
классификаторы с одинаковым входным регистром при периодах 20 и 10 нс,
а также реализует два прототипа с самопроверкой. Для обоих сравниваемых
классификаторов запускается функциональная симуляция после синтеза на
2331 векторе. Выполняется размещение и трассировка; битовый поток не
создаётся. Прогон может занять заметное время. Успех обозначен строкой
`PR23_DONE` в Tcl Console; сообщение `BUILD_DONE` относится только к
одному этапу.

Все результаты лежат в `vivado_pr23/results/`. Для каждого варианта
сохраняются лог синтеза и отчёт ресурсов. Для трассируемых вариантов
добавляются `implementation.log`, `utilization_routed.rpt`,
`timing_routed.rpt`, `critical_paths.rpt`, `route_status.rpt`,
`drc_routed.rpt`, `routed.dcp` и краткий `result.txt`.

Для завершения отчёта передайте **всю папку `vivado_pr23/results/` одним
ZIP-архивом** и скрин Tcl Console со строкой `PR23_DONE`. При ошибке
передайте полный текст первой строки `ERROR:` и файл
`vivado_pr23/bnn_pr23.runs/synth_1/runme.log` либо
`vivado_pr23/bnn_pr23.runs/impl_1/runme.log` для упавшего этапа.

## Что сравнивается

Варианты `baseline_20` и `pipeline_20` получают переменные внешние
признаки через одинаковый входной регистр и используют одни и те же
веса и кристалл. Различие — регистр восьмибитного результата между
слоями A и B в `bnn_classifier_pipelined`. Оба принимают один вектор
каждый такт. Конвейер добавляет один такт задержки отдельного ответа;
эффект по частоте и расходу ресурсов определяется только отчётами
трассировки. Варианты `_10` проверяют ту же схему при цели 10 нс.

`pr3_prototype_20` и `pr3_pipeline_20` используют встроенные 64
контрольных вектора и проверяют автомат подачи, счётчики и завершение.
Их ресурсы нельзя использовать для оценки ускорения вычислительного
ядра: постоянный тестовый набор допускает оптимизацию части схемы.

Без конкретной платы и её схемы выводы не назначаются. Предупреждения
DRC о контактах и стандартах ввода-вывода фиксируются в отчёте.
