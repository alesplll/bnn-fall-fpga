# bnn-fall-fpga

Бинарный нейросетевой классификатор для детектирования падения
человека по данным инерциальных датчиков (акселерометр + гироскоп).
Подготовлены программная и RTL-модели, а также прототип с самопроверкой.
RTL проверена симуляцией и синтезирована; прототип размещён и
трассирован в Vivado 2022.2 для Artix-7 `xc7a100tcsg324-1`.

Пять признаков (пиковое ускорение, угол наклона, пиковая угловая
скорость, jerk, дисперсия после пика — см. [`model/README.md`](model/README.md))
извлекаются из сигнала и подаются на маленькую бинарную нейросеть
5→8→1: первый слой — fixed-point (int8), второй — истинно бинарный,
считается через XNOR + popcount вместо умножения. В первом слое остаются
знаковые целочисленные умножения; операций с плавающей точкой нет.

## Что где лежит

- **[`model/`](model/)** — код модели: обработка датасета SisFall,
  извлечение признаков, обучение бинарной сети (NumPy,
  BinaryConnect/STE), её точная целочисленная реализация и метрики
  качества. Всё воспроизводимо с нуля (`model/README.md`).
- **[`dataset/`](dataset/)** — готовый датасет для обучения/проверки:
  один csv, где каждая строка — уже посчитанные 5 признаков + метка
  класса (не сырые сигналы). Описание колонок — в `dataset/README.md`.
- **[`weights/`](weights/)** — результат обучения в виде, готовом для
  аппаратной части: квантованные веса (`.mem`, hex, `$readmemh`) и
  эталонные тестовые векторы (вход → ожидаемый выход) для сверки
  результатов симуляции и работы в железе. Формат каждого файла
  расписан в `weights/README.md`.
- **[`rtl/`](rtl/)** — RTL-модель классификатора на Verilog,
  самопроверяющийся тестбенч, граничные тесты и сценарий создания проекта
  Vivado 2022.2. Проверка сверяет выход и промежуточные значения с `weights/`.
- **[`report/`](report/)** — единый отчёт по практическим работам № 1–3
  в DOCX и PDF, снимки экрана Vivado и текстовые отчёты реализации.
  Предыдущие версии отчёта и сценарии сборки сохранены.
- **[`fpga/`](fpga/)** — верхний модуль прототипа, его тестбенч,
  ограничение тактового сигнала и сценарии Vivado для ПР3.
- **[`defense/`](defense/)** — памятки для защиты ПР2 и ПР3 с пояснениями
  и полными листингами исходников.

## Результат практической работы № 2

В Vivado 2022.2 поведенческая симуляция XSim прошла полный набор из
2331 эталонного вектора (`PASS: 2331 vectors`). Синтез RTL-модуля
завершился успешно; получены логическая схема и отчёт использования
ресурсов: 629 Slice LUT, 2 Slice Register, 45 Bonded IOB и 1 BUFGCTRL.
Скриншоты проекта, кода, симуляции и синтеза включены в
[`report/Отчет_ПР1_ПР2_Рябец_Головин_Гришин.pdf`](report/Отчет_ПР1_ПР2_Рябец_Головин_Гришин.pdf).
Порядок воспроизведения результата описан в [`rtl/README.md`](rtl/README.md).

## Результат практической работы № 3

Поведенческая симуляция XSim подтвердила правильность 64 ответов
прототипа, обнаружение намеренно изменённого эталонного бита и
повторный успешный прогон. Vivado 2022.2 завершил размещение и
трассировку: проложены все 760 трассируемых цепей без ошибок.
После трассировки заняты 646 Slice LUT, 29 Slice Register, 209 Slice,
21 Bonded IOB и 1 BUFGCTRL. При периоде 20 нс WNS равен +5,270 нс,
TNS — 0. Это результат для внутренних синхронных путей: задержки
внешних входов и выходов не заданы.

Ограничение задаёт только тактовый сигнал. Выводы платы и стандарты
ввода-вывода не назначены, поэтому DRC содержит NSTD-1, UCIO-1 и
CFGBVS-1; битовый поток и проверка на плате не выполнялись. Данные,
иллюстрации и полный листинг приведены в
[`едином отчёте ПР1–ПР3`](report/Отчет_ПР1_ПР2_ПР3_Рябец_Головин_Гришин.pdf).
Команды запуска описаны в [`fpga/README.md`](fpga/README.md).

Веса самой сети крошечные (57 параметров, ≈77 байт «сырых» данных —
почти вся сложность в признаках, а не в модели), поэтому файлы в
`weights/` — это в основном удобочитаемый hex-текст для `$readmemh`,
не бинарная упаковка.

## Поток данных

```
SisFall (сырые данные) -> model/ -> dataset/ (признаки)
                              |    -> weights/ (веса + эталон) -> rtl/ -> fpga/
                        обучение и валидация модели
```

`model/` — единственная часть, где есть Python/NumPy и обучение.
Дальше по цепочке всё воспроизводится строго по датасету, весам и
тестовым векторам из `dataset/` и `weights/`, без переобучения. Команды
симуляции и порядок открытия проекта Vivado описаны в [`rtl/README.md`](rtl/README.md).
